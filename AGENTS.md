# AGENTS.md

Guide for AI agents working in this repo: the Homebrew tap for StaffOps tools
(`brew install staffops/tap/<tool>`). Overview: [README.md](README.md).

## Branches

| Branch | Use |
|---|---|
| `main` | The only branch, and what `brew` reads. GoReleaser commits cask updates here directly |

## Layout

```
Casks/<tool>.rb      # generated by GoReleaser in the tool's repo (header: "DO NOT EDIT")
catalog-info.yaml    # Backstage entities
```

## Commands

There is no build or CI here. To check a cask after a change (macOS with Homebrew):

```bash
brew tap staffops/tap
brew install --cask staffops/tap/kube-node-viewer
brew audit --cask staffops/tap/kube-node-viewer
```

## Rules

- **Do not edit generated casks.** Change `homebrew_casks` in the tool's `.goreleaser.yaml`
  (for example [kube-node-viewer](https://github.com/StaffOps/kube-node-viewer/blob/main/.goreleaser.yaml))
  and let its next release rewrite the cask; a hand edit is overwritten.
- **English only**: README, docs, CHANGELOG and commits.
- **Conventional Commits** for hand-made changes (`chore(catalog): ...`, `docs: ...`). GoReleaser's
  own commits (`Brew cask update for ...`) are the exception.
- **CHANGELOG** `[Unreleased]` and [docs/handoff.md](docs/handoff.md) change with any hand-made change.
- **Secrets are never committed.** GoReleaser pushes with `HOMEBREW_TAP_GITHUB_TOKEN`, a secret
  of the tool's repo, not of this one.

## Pitfalls

| Pitfall | What to do |
|---|---|
| The binaries are not notarised by Apple, so Gatekeeper blocks the first run | The cask's `postflight` removes the quarantine attribute; keep that hook in `.goreleaser.yaml` |
